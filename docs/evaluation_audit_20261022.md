# 评测规模与指标审查

审查日期：2026-10-22。依据项目现有 `evaluation/evaluate.py`、v1 数据集及本次新增的 v2 数据集；没有进行实时 RAG 或 Judge 评测。

## 题量判断

原来的 200 题（dev 80 / test 120）已经能做初步回归，比 6 题 smoke 测试充分。但原集有 50 个知识主题、93 个不同的证据页，多个问题重复考查同一主题；不足以仅凭一两个百分点的变化就证明改进稳定。对当前 semantic splitter 和父子块优化，跨页证据与代码上下文的覆盖也需要加强。

本次扩充到 320 题：dev 120 / test 200。新增 40 个知识主题标签，合计 90 个；有证据的问题由 150 增至 250，所选证据页从 93 增至 160。数据与字段说明见 [评测集](../evaluation/datasets/README.md)。2026-10-24 已将数据统一到该目录，题目内容不变，重复的逐题审阅副本已移除。本文中的 v1/v2 指历史扩充批次。

这足以作为该四本书项目的下一阶段开发基准，不是“达到某个固定题数就可靠”。如果要报告小幅提升，应看成对差异、类别分布、重复运行波动和标注质量。作为数量级示例，独立二项样本且真实比例接近 50% 时，简单正态近似的 95% 误差半宽为 `1.96*sqrt(0.25/n)`：n=120 约 8.9 个百分点，n=200 约 6.9 个百分点。这不是本项目的实测置信区间；主题相关性和评分缺失还会影响有效样本量，各指标的有效 n 也不同。

## 已有指标与实际口径

| 维度 | 当前代码已有 | 使用时要注意 |
|---|---|---|
| 检索 | 页 Hit@K、标注页 Recall@K、MRR@K | 命中所选答案页，不等于命中具体证据；MRR 是首个命中标注页的片段排名 |
| 生成上下文 | 全部最终上下文的页命中/召回、返回文档数 | Agent 统计 final context；检索基线统计直接召回，两者不是同一阶段 |
| 路由 | 二值正确率、三路正确率、动作计数 | 缺少混淆矩阵和每类 P/R/F1；缺失信息题的二值标签有政策歧义 |
| 答案质量 | Judge 的 answer_correct、grounded | 当前是答案级布尔判断，不是逐要点或逐声明的连续评分 |
| 引用 | 是否存在编号、编号合法率、Judge 判断 citations_supported | 合法编号不等于有效支持；尚非逐声明的引用精确率/覆盖率 |
| 拒答 | 不可回答题拒答率、可回答题误拒答率 | 总体不可回答组包含澄清题，必须结合 by_category，避免把追问简单当失败 |
| 运行 | 成功数、错误率、workflow_error_count、重试与节点轨迹 | 成功返回也可能包含内部工作流错误，两个口径都要看 |
| 速度 | 成功请求 P50/P95、节点耗时、初始化耗时 | 要统一预热；少量样本的 P95 不稳定，失败请求不进入成功延迟分布 |
| 资源 | LLM 调用数、API 返回的 Token、Judge 单独使用量 | 缺失 usage 不等于零；未完整计入 Embedding、重排硬件成本及货币费用 |
| 裁判可靠性 | 评分成功/失败、重试/文本兜底、矛盾结果计数 | 应报告评分覆盖率，不能只展示成功评分的均值 |

这些维度已能发现常见系统问题，但不足以完整证明当前 chunk 优化有效。

## 建议补充的优先级

### 优先 1：具体证据召回与上下文有效性

保留页级指标作历史对照，另加入证据片段/要点级 Recall、上下文相关性或 Precision。对于跨页问题，检索到其中一页不能当作完整证据成功；对于长父块，包含更多页面也不必然更好。

v2 已提供可回查的证据原文和规范化字符区间，但**现有评测器没有消费这些字段**。后续需把返回块的 `source_spans` 与相同提取器下的证据进行对齐，处理空白、公式和等价出处，不能直接拿 PDFium 偏移截 PyMuPDF 文本。多条证据有时是互补关系、有时可能是替代来源，严格的“全部证据齐全率”还需逐题补充证据组语义。

证据召回与上下文相关性应分开报告。现有参考证据不是整个语料的穷尽相关性标注，不能因为某个召回片段不在 gold 列表就直接认定它无关。需要进一步判定其是否支持答案；长上下文还应同时报告实际 Token 使用量。

比较 semantic splitter、普通切分与父子块时，应保持相同 Embedding、召回候选规模、reranker、生成模型和上下文 Token 预算。可分别记录初始召回、重排后和最终上下文三个阶段，避免把扩大上下文的收益误记为排序算法收益。

### 优先 2：评分要点覆盖及引用支持

利用 `rubric.required_points` 判断每个关键点是否正确覆盖，报告“正确覆盖点数 / 适用点数”，并保留整题正确率。只有部分答案正确时，不应与完整答案无法区分。这个逐点分数目前**尚未实现**。

将关键声明和其引用逐条对应，分别衡量“引用是否支持声明”和“需要依据的声明是否提供了引用”。当前 `grounded` 和 `citations_supported` 的答案级布尔值不能直接称为 Ragas Faithfulness 或 citation precision/recall。

Ragas 官方指标目录分别列出 Context Precision、Context Recall、Response Relevancy、Faithfulness 及 Rubrics based scoring，可用来对齐评价维度；不必为了指标名称引入整套框架。[官方指标目录](https://docs.ragas.io/en/latest/concepts/metrics/available_metrics/)

### 优先 3：路由类别、评分覆盖与不确定性

对无歧义的三路请求报告混淆矩阵与 macro-F1，查看检索、直接回答和追问分别错在哪里。信息缺失题应允许合理的多种处理路径，或单独统计，不能强制检索才算正确。当前 `acceptable_routes` 是数据标注，尚未接入评分。

报告每项指标有效 n、Judge 覆盖率、各题型结果及成对差值。若重复问题集中于同一主题，不能把逐题 bootstrap 的独立性当作已成立；应先明确主题族或连接簇，再做适合该分组的成对重采样。跨书题连接多个主题时尤其需要处理依赖关系。

从最终配置中抽取覆盖不同类型的样本做独立人工评分，用于校准 Judge。相同裁判、Prompt 和温度有助于比较，但不等于裁判天然正确。

### 暂不必堆叠的指标

没有分级相关性标注时，不宜直接把页命中伪装成 nDCG。BLEU/ROUGE 可以描述文字重合，但不能替代教材问答中的事实正确性。工具调用准确率适合有明确工具选择与参数金标准的任务，当前主要是三路 RAG 流程，优先把现有关键链路测准。

## 数据质量与验证结果

- 320 个唯一题号和唯一规范化问题；新增 40 道 dev、80 道 test。
- 原 v1 数据文件和四本 PDF 的 SHA-256 与原 manifest 一致，v2 中继承的 200 条记录未改变。
- 377 处证据标注在相应提取器的规范化页文本中逐一精确匹配。
- dev/test 标注主题与 gold 页交叉均为 0；这不是所有语义相关性都为 0 的证明。
- 对包含新题的跨集问题做了字符 4-gram Jaccard 排查，最高约 0.141；检查最高的 10 对未发现直接同题改写跨集。词面筛查不能证明没有深层语义泄漏。
- 对 4 个公式/代码页作了视觉抽查，见 [validation_report.json](../evaluation/datasets/validation_report.json)。新题的计算、反例和综合答案由助手核对，独立人工复核待完成。

无答案新增题仍主要为缺少外部事实；错误前提题是可回答的纠错题。新增集不构成穷尽的“语料中确实无答案”压力测试，也尚未覆盖真实用户多轮会话、文档冲突、文档内提示注入、OCR 噪声等场景。这些应按下一阶段用途另建专项集，而非为了凑题数混入当前版本。

## 如何使用测试结果

扩充后的 test 含旧 test 的 120 题。若旧报告已经指导过修改，不能把全体 200 题包装成全新盲测。2026-10-24 整理后，新增 80 题保留在统一的 `test.jsonl` 中，仍沿用 `v2-` 题号前缀，不再单独保存增量副本。是否可作为保留集取决于是否参与过调参，不能仅根据题号前缀判断。

只用 dev 调参，保留 test 做冻结后的比较；简历上再写实际测得的改进、有效题数、数据版本和公平对照条件。当前可描述“构建四本书、320 题的带证据标注评测集”，不能凭本次扩充写“准确率提升”或“已通过320题测试”。
