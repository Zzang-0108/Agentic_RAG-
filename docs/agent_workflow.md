## 三路路由

| 动作 | 适用情况 | 后续流程 |
|---|---|---|
| retrieve | 教材知识、专业原理、明确的资料查询，包括口语化描述 | 检索 → 重排 → 整组证据检查 |
| direct | 问候、感谢、简单计算、输入完整的格式转换等 | 直接完成任务 |
| clarify | 对象/前文/附件缺失，或需要用户个人日志等外部信息 | 提出具体澄清问题，暂不检索 |

明显缺少指代对象的短请求先走规则，例如“比较这两个方案”“继续解释刚才那一段”。规则只处理没有具体对象的输入，不按评测题号匹配；包含实际对象的请求仍交给路由模型。规则命中时无需模型调用。

路由解析失败会重试一次，仍失败则保守进入检索，并在 trace 中记录异常，不默认让模型自由回答知识问题。

## 整组证据检查

一轮使用一次逻辑检查，而非为每个片段串行调用模型；解析失败最多再调用一次。

- complete：已覆盖原问题的各个方面，进入生成。
- partial：只有部分支持；针对 missing_points 生成一条补充查询，继续检索。
- none：没有支持证据；有新查询且预算允许时重试，否则明确说明信息不足。
- needs_input：缺的是用户数据而非教材知识，提出补充信息请求。
- error：程序侧状态，表示接口或校验失败；与“不相关/没有答案”分开记录。

检查返回 covered_points、对应资料编号、missing_points、followup_query 和 reason。当前证据检查要求模型在正文输出 JSON，再用 Pydantic 严格校验；路由使用工具调用并支持正文 JSON 兜底。这样处理是因为实际回归发现当前模型在长上下文下会复述工具定义，不能把这种输出当成有效判断。解析失败仍会显式报错。

程序校验状态一致性与编号范围；它不保证 LLM 的语义判断一定正确，仍需评测和人工抽查。

补充查询由检查节点一起产生，不另调模型重复改写。每轮始终对照原始问题；已经确认的资料与新资料合并后再检查，按来源、页码、正文去重。资料过滤后重编号，保证生成引用和最终上下文一致。

最多补搜两轮，默认最多保留 15 个片段（RAG_MAX_EVIDENCE_DOCS）。达到预算时，有部分依据则回答有支持的部分并说明遗漏；没有依据则使用固定的不足说明，不让生成模型对空上下文补写事实。重复查询会提前停止。对整个检索池都为空的情况也会提前停止。

优化切分模式还对每轮合并后的格式化上下文执行 `RAG_MAX_CONTEXT_TOKENS` 预算。父块放不下时尝试保留实际命中的子块；长度使用配置的 tokenizer 计量，不等于生成模型的精确计费 token 数。

生成提示词要求逐项回答、简洁解释、引用证据，并核对数字及前后结论的一致性。这是提示约束，不是独立的事实验证器。

## 记录与评测

`details.jsonl` 新增 route_action、final_action、evidence_status、covered_points、missing_points、queries、stop_reason 和 trace。trace 按节点记录耗时、LLM 调用/已报告 Token，以及结构化输出的工具/正文/重试诊断；检索节点包含重排前候选、重排分数、最终选择和本轮证据池。

日志包含知识库片段，请按知识库相同的权限管理。Token 缺失仍记为 null，不能当作零成本。`workflow_error_count` 单独统计检索或证据检查异常后的降级回应；这类回应虽然完成了程序执行，也不能当作证据检查成功。

补搜后最终上下文可能超过 5 个片段，因此同时报告前 5 个片段的页指标与 `all_context_page_hit` / `all_context_page_recall`（全部生成上下文）。两种口径不可混用。页命中只表示命中标注页，不保证片段包含所需的具体证据。

`summary.json` 保留二分类 route_correct，并记录三路 route_action_correct。unanswerable 题的策略标签存在歧义，因此不进入严格三路指标；旧标签和旧指标保留。历史 v1 开发集对应 68 道适用题，当前 v2 开发集历史报告的分母为 104；以当次报告为准。输出可解析也不等于裁判判断正确。

报告保存 rag_core/*.py、rag.py、file_loader.py 和评测脚本的哈希，以及重排配置和流程预算。不同版本比较应固定模型、题目、检索候选数和裁判；多轮策略可能使用更多上下文，应同时比较调用数、Token 和延迟。

在项目根目录运行（使用已安装依赖的 torch_gpu 环境）：

```powershell
python -m unittest discover -s tests
python -m unittest discover -s evaluation -p 'test_*.py'
python evaluation/evaluate.py --dataset evaluation/datasets/dev.jsonl --mode agent --judge --judge-model deepseek-flash --warmup-rerank
```

`--warmup-rerank` 将权重加载及首次前向放入初始化时间；常规交互仍可懒加载。小规模回归可用 `--ids cd-01 dd-03 p03-3` 选择题目。实时评测会调用已配置的模型接口；离线测试不会。

开发集用于调试与对照。测试集需在流程与参数冻结后运行；本次开发不使用测试答案来修改流程。
