## 可直接使用的简历版本

**面向技术文档的证据驱动 Agentic RAG 问答系统**

**技术栈：** Python、LangGraph、LangChain、FAISS HNSW、BM25、BGE Embedding / Reranker、PyTorch。

**项目简介：** 面向机器学习与大模型技术文档，构建支持多文档检索、缺失信息澄清、按需补搜及引用溯源的知识问答系统。

- **文档与切分：** 实现 PDF 结构清洗、章节恢复及基于邻句向量距离的语义切分，构建覆盖 4 本技术书籍的 2006 个父块、4676 个检索子块；采用子块召回、重排后扩展父块的策略，并通过上下文预算与子块回退控制输入长度。
- **检索优化：** 基于本地 BGE 中文向量模型与 FAISS HNSW 实现稠密检索，融合 BM25 与加权 RRF，并引入 BGE 交叉编码器重排；在已完成开发集的 92 道有证据知识题上，相较未重排的混合检索，页级 Hit@5 从 69.6% 提升至 76.1%，MRR@5 从 0.552 提升至 0.651。
- **Agent 决策：** 基于 LangGraph 编排检索、直接回答、澄清三路路由，将逐篇相关性筛选改为整组证据充分性检查；按完整、部分、无依据或缺失用户输入决定生成、定向补搜、拒答或澄清，并通过重复查询检查与重试预算控制补搜。
- **回答与诊断：** 对路由及证据检查输出进行 Pydantic 校验，检查证据编号范围，合并并重编号已确认资料后生成带引用的回答；支持部分回答、有限重试及异常记录，通过节点 trace 定位协议失败与过度拒答。
- **评测与工程：** 构建 320 题评测集，划分 120 题开发集与 200 题测试集，覆盖多证据、跨书、不可回答及澄清等场景；实现检索指标、LLM 裁判、节点耗时与调用量追踪，并保留源码哈希和逐题报告用于版本对比。

## 一页简历空间较紧时的四条版本

**面向技术文档的证据驱动 Agentic RAG 问答系统**

**技术栈：** Python / LangGraph / FAISS HNSW / BM25 / BGE / PyTorch

- 实现 PDF 结构清洗、语义切分与父子块检索，基于 4 本技术书籍构建 4676 个检索子块；采用本地 BGE 编码、向量缓存及索引指纹校验，支持缓存命中后直接恢复检索服务。
- 构建 BM25 + HNSW 双路召回、加权 RRF 融合与 BGE 重排链路；在开发集 92 道有证据知识题上，相较混合检索，页级 Hit@5 从 69.6% 提升至 76.1%，MRR@5 从 0.552 提升至 0.651。
- 基于 LangGraph 实现检索 / 直答 / 澄清三路路由，以整组证据充分性检查驱动定向补搜；合并已有证据、校验引用编号，并支持部分回答、重复查询检查与重试预算控制。
- 建立 120 题开发集、200 题测试集及自动评测脚本，支持页级检索指标、回答正确性与引用支持的 LLM 裁判、节点耗时和调用量记录；通过逐题 trace 定位严格校验引发的过度拒答，并完成版本回退。

## 面试时的一分钟介绍

我围绕技术文档问答做了一个 Agentic RAG 项目，主要处理片段缺少上下文、检索相关但证据不完整，以及补搜过程难以控制的问题。文档侧使用结构和语义切分，检索侧用 BM25 与 BGE 向量双路召回，经 RRF 融合和交叉编码器重排后扩展父块。已完成的开发集对照中，重排将页级 Hit@5 从 69.6% 提升到 76.1%。我还建立了 320 题评测集，分别记录检索质量、回答质量和节点开销。后来尝试加强要点和引用约束时出现了明显退化，我通过逐题 trace 定位到结构化协议和局部校验失败引发的过度拒答，先回退到已有评测依据的版本，再计划逐项修正与验证；修正方案尚未实施。
