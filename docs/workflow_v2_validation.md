# Agent 流程 v2：实现与验证记录

日期：2026-10-19。代码改造与离线验证已完成；完整开发集的真实模型验证尚未完成，原因是供应商账户资源不足。

## 已实现

- 三路路由：`retrieve` 查知识库、`direct` 完成简单任务、`clarify` 索取缺失对象或输入。部分明确缺少指代对象的短请求由规则处理。
- 整组证据充分性检查：用已有要点、缺失要点、证据编号判断是否能回答原问题，替代逐片段串行判相关。
- 按缺失点补搜：保留已支持的证据，合并去重，最多补搜两轮；重复查询提前终止。预算耗尽后仅回答有依据的部分或说明无法回答。
- 诊断记录：逐节点耗时、调用数、已报告 Token、重排候选及分数、每轮查询与证据判断、最终回答动作。
- 评测保护：正文 JSON 严格校验、解析失败显式记录；账户资源耗尽时停止后续评测；逐题保存明细和汇总。

运行与字段说明见 [Agent 问答流程](agent_workflow.md) 和 [评测说明](../evaluation/README.md)。入口仍是 `python rag.py`。

## 已知限制与待验证项

1. 当前小模型仍可能对明确的教材问题过度澄清，也可能在证据检查时额外要求题目未问的细节。最后补充了知识库书目和“只核对原问题要求”的提示约束；这两处最后调整仅完成离线验证，尚无新的在线成绩。
2. 证据检查和生成都由模型完成；格式、编号合法不等于内容正确。提示词中的一致性要求也不是独立的事实验证器。
3. 多轮补搜可能提高覆盖，也可能增加延迟或引入无关资料。需同时比较正确率、按类表现、调用数、Token 和 P50/P95，不能仅凭结构改造断言效果提升。
4. 页级金标较粗；命中标注页不保证命中具体证据。当前评测集的参考答案与裁判结果仍需人工抽查。

目前适合在项目介绍中描述这些实现与评测机制；不要写“本次改造将准确率提高到某数值”。已有旧报告的成绩也不能作为当前流程的成绩。
